## Course Material Submissions

Confirmed 2026-07-14:

- Materials optionally declare submission actions as `submissions` entries with `name` and `link` fields. The contract is defined in `Models/CourseFrontMatter.cs` and `Models/SubmissionLink.cs`; rendering lives in `Components/Pages/Blog.razor`.

## Native Course Material PDFs

Confirmed 2026-07-14:

- The Markdown material (YAML frontmatter plus body) is the source of PDF content. Every file in `Content/Materials` should attempt to produce a native static PDF, and the Download action should prefer that artifact. Keep `downloadLink` as an intentional external redundancy/fallback: if that material's PDF generation fails, render its existing external link instead and continue the site build. If both generation and fallback are unavailable, omit only that material's Download action and surface a prominent CI warning/step summary. Bookings, projects, events, and FAQs use separate frontmatter types and must not enter this pipeline.
- PDF generation runs during application startup immediately before BlazorStatic generation. `PdfGeneratorService` discovers non-draft Markdown files recursively from `Content/Materials` itself because BlazorStatic's post collection is not populated at that point. It publishes a per-route `PdfGenerationManifest`; `Blog.razor` resolves generated PDF, then nonblank `downloadLink`, then no Download action. A document-level failure is isolated and never stops the site build.
- `dotnet run` is the single local and CI entry point. The pinned `Dependencies/RensMarkdownTemplates` project restores its Node dependencies before Tailwind or PDF generation, while application startup bootstraps pinned Pandoc 3.10 and Tectonic 0.16.9 archives for the current Windows/Linux x64 runtime. Downloads use checksums, partial files, retries, extraction staging, and executable validation. Tectonic receives the pinned remote bundle URL and keeps its range cache under `artifacts/tectonic-cache`; it does not download the multi-gigabyte bundle eagerly.
- Frontmatter supports an optional `pdf` map with an allowlisted template name and arbitrary template variables. Templates live under `Dependencies/RensMarkdownTemplates/templates/<name>/`; the selected directory is fingerprinted in full. The default template uses bundle-owned OpenType fonts, native Pandoc highlighting macros, bounded images, and table support, so output does not depend on host fonts or a host TeX installation.
- Each document fingerprint length-frames its logical inputs: generator schema/version, complete raw Markdown, selected template directory, the shared toolchain manifest and `package-lock.json`, Mermaid configuration, referenced local media, and shared PDF assets. Therefore any corresponding frontmatter or body change invalidates that document. Cache state lives in `artifacts/material-pdfs/state`; content-addressed PDFs live in `wwwroot/pdfs`. Missing, corrupt, mismatched, inactive, or orphaned entries are invalidated/pruned, and both PDF and state publication are atomic.
- Mermaid definitions are rendered as vector PDFs through the shared package's Node CLI entry point and configuration. A Mermaid failure falls back only that document. Process execution uses `ArgumentList`, drains redirected output, distinguishes cancellation from timeout, and kills timed-out process trees.
- Generated PDFs must be excluded from SDK static-web-asset discovery in the early-imported `Directory.Build.props`; BlazorStatic copies the physical directory after startup generation. That same file excludes nested `bin`, `obj`, `tests`, `output`, `artifacts`, and `node_modules`, preventing recursive test/build output from being copied into the main output.
- CI caches toolchain/browser inputs separately from per-document PDF state and generated artifacts. The production run writes a GitHub step summary for generation/fallback outcomes. Local diagnostics and customization are documented in `README.md`.
- Verification path: delete `artifacts/pdf-toolchain`, `artifacts/tectonic-cache`, `artifacts/material-pdfs`, and `wwwroot/pdfs`, then run the documented production `dotnet run --no-launch-profile --configuration Release`. On 2026-07-29 the unified-profile production run generated all 42 discovered PDFs with zero fallbacks, and all 230 .NET tests passed. After the rubric-landscape update, a cold run regenerated all 42 PDFs with zero fallbacks and the unchanged warm run reported 42 cache hits in 0.15 seconds. Retain the broader browser and script suites as release gates.

## Static Generation

Confirmed 2026-07-14:

- Generated article pages use `output/articles/{slug}.html`, not `output/articles/{slug}/index.html`. This was verified by generating and locally rendering a temporary material through the production entry path.
- Run local production generation with `dotnet run --no-launch-profile` after setting `ASPNETCORE_ENVIRONMENT=Production`. The repository launch profiles force Development and otherwise start a persistent server; this was confirmed by comparing the timed-out default-profile run with a successful production run.
- The production run also requires `TERM_START` and `TERM_END` (e.g. `2026-01-15` / `2026-05-31`); without them `BuildTimeProvider`'s static constructor throws `TypeInitializationException` (`DateTime.Parse(null)`) and the build exits 82. `SHOWCASE_MODE=true` is optional but matches CI. Confirmed 2026-07-15 by a failing then passing run.
- The home page must pass `BlazorStaticContentService<CourseFrontMatter>.Posts` into `PostsList`, which then applies `CourseContentProvider.GetVisiblePosts(sourcePosts)`. During static generation, a provider can capture the service before its post collection is populated; using its parameterless overload produced tag chips but an empty card grid. `BlogPageTests.Home_UsesParsedPostsEvenWhenProviderCapturedAnEmptyService` reproduces this lifecycle split.
- Local CSS and JavaScript URLs use a 12-character SHA-256 content hash; an assembly timestamp is insufficient because static-asset-only edits need not rebuild the assembly. Service-worker shell changes still require a cache-name bump. Verify generated HTML hashes against the referenced files and run `home.spec.js` in a real browser.
- **Active-course gating (2026-08-06) supersedes the earlier showcase-only guidance.** `ACTIVE_COURSES` (comma-separated env var, set in the CI workflow and all `launchSettings.json` profiles, e.g. `cmsc-124,cmsc-131`) defines the courses offered this term. Non-showcase visibility: tagged content is course-scoped and visible iff any tag matches an active course; untagged content falls back to the term-window date check. Showcase mode bypasses everything (term window, active courses) and just hides drafts. Applied in `CourseContentProvider`, `FAQContentProvider`, `BookingContentProvider` (new), and `CalendarEventProvider.GetVisibleCustomEvents`; `CalendarEventFrontmatter` carries `Tags` for course-scoped events. Term dates remain in `TERM_START`/`TERM_END`; term-end empty state and future-release checks still apply. Verified 2026-08-06: 142 .NET tests, 111 JS tests, 7 Python feed tests, and a production run showing cmsc-125 booking/FAQs/calendar event hidden while cmsc-124/cmsc-131 articles and all projects remain.
- **Round 2 (2026-08-06):** The gating is applied consistently across every surface. (1) `WebsiteKeys.RemoveHiddenArticlePages` (wired as `AfterContentParsedAndAddedAction` on the materials service) drops individual `articles/{slug}` pages for posts that fail visibility — direct URLs no longer serve hidden materials. (2) The home page's `CourseFilter` chips derive from visible posts, so inactive courses don't appear. (3) `generate_feed.py` mirrors article visibility: tagged posts require an active course, untagged posts keep the term window; term-end empty feed and showcase skip unchanged. Feed item count equals generated article page count. (4) Tests use dedicated fixture tags (`fixture-course-a`/`-b` active, `fixture-course-c` inactive) in `TestEnvironmentFixture`'s `ACTIVE_COURSES` — never real course tags. Verified: 145 .NET tests, 111 JS tests, 10 Python feed tests, production build with zero `articles/cmsc-125-*` pages and active-only home chips, and a feed run whose 15 items match the 15 generated article pages.
- **Strict term window (2026-08-06) supersedes carryover:** frontmatter outside the `TERM_START`--`TERM_END` window is not published at all — even for active courses. Articles/FAQs must be in-window AND (if tagged) course-active; showcase still bypasses everything. Applied in `CourseContentProvider`/`FAQContentProvider` (`IsVisibleOutsideShowcase`) and mirrored in `generate_feed.py` (window check for all posts, then active check for tagged). Result: with the Aug–Dec 2026 term, all 2025-08-dated materials are unpublished (0 article pages, empty feed, empty materials page) until content is re-dated/re-released; bookings, custom events, and projects are unaffected. Verified: 167 .NET / 111 JS / 11 Python tests, production build with 0 article pages and 0 feed items, and the full e2e suite (104 passed, 35 conditional skips, 0 failed).
- **CI gate (2026-08-06):** `build-and-publish.yml` runs the full .NET test project (`dotnet test tests/Ren.Courses.Tests/Ren.Courses.Tests.csproj --configuration Release`), JS jest tests, and Python feed tests. The RSS-feed step passes `ACTIVE_COURSES` to the generator — omitting it makes the generator see an empty active set and drop every tagged post. 165 .NET / 111 JS / 11 Python tests, plus the two production builds in CI, are the CI verification path. Playwright e2e is deliberately NOT in CI — the suite takes too long for GitHub runners; AGENTS.md §5 mandates running it locally before presenting/shipping (see README "E2E (Playwright)" for the local recipe).

## Interactive Diagrams

Confirmed 2026-07-15 (marker-based placement update):

- Materials optionally declare `diagrams`, each with `title`, optional `description`, `key` (kebab-case slug), and ordered `steps`. Every step has a `title`, optional `description`, and a complete Mermaid definition in `mermaid`. The contract lives in the shared `MarkdownFrontMatter`, `LearningDiagram`, and `LearningDiagramStep` models.
- Diagrams render ONLY where the body references them with an HTML-comment marker on its own line: `<!-- diagram: key -->`. Unreferenced diagrams never render (strict mode). Same key twice produces two widget instances. Marker determines placement in both web page and generated PDF — achieved by construction: web splits rendered HTML at the verbatim comment; PDF substitutes the same marker line in body markdown before Pandoc.
- Shared `DiagramMarkers` is the single syntax owner: `MarkerLine` regex for own-line matching, `FindReferencedKeys` for PDF path, `Substitute` for marker replacement, `ResolveSegments` for web path. Key format validated by `KeyFormat` regex (`^[a-z0-9]+(?:-[a-z0-9]+)*$`).
- `Components/InteractiveDiagram.razor` renders diagrams with Previous, Next, and Play controls. `wwwroot/js/interactive-diagrams.js` lazy-loads pinned Mermaid 11.16.0 only on pages with widgets, uses strict security, pre-renders every step before enabling controls, rerenders every step for site theme changes, and preserves authored source when loading or rendering fails.
- Diagram sources must be excluded from `code-features.js` and hidden synchronously before Mermaid loads; otherwise the raw definition flickers and receives an empty `.code-wrapper`. Do not trust Mermaid's generated viewBox or intrinsic `max-width`: some client renders produced a correctly sized stage with a roughly 40px drawing. Temporarily make hidden steps measurable offscreen, rebuild each SVG viewBox from `.root.getBBox()` plus padding, and enforce fill dimensions inline with `!important`; repeat synchronously whenever a step is shown. Derive the stable widget ratio from those normalized bounds.
- The 26rem-wide stage is bounded to 6rem–18rem high, so square and horizontal diagrams remain proportionate without resizing between steps. Verify YAML and static markup with `StaticGenerationTests` and `BlogPageTests`; verify controls, eager rendering, viewport normalization, stable aspect metadata, error fallback, single-step behavior, and theme refresh with `interactive-diagrams.test.js`. `interactive-diagrams.spec.js` deliberately corrupts a step to a 40px SVG with a 2000×2000 viewport and verifies repair in Chromium and Firefox.
- Content hygiene tests (`tests/Ren.Courses.Tests/DiagramContentHygieneTests.cs`) scan all `Content/Materials/**/*.md` files and fail loudly on: missing/invalid/duplicate `key` values, body markers referencing undeclared keys, and diagrams with steps that are never referenced. Runtime stays graceful (unknown-key markers produce a log warning; unreferenced diagrams are silently skipped).
- `GeneratorSchemaVersion` 3→4 (2026-07-15) because diagram placement logic changed from prepending-all-diagrams to marker-based substitution. 4→5 (2026-07-15) for float-pinning fix + fence-aware marker scanning. 5→6 (2026-07-15) for Pandoc list-parity fix + fence state-machine rewrite — both change generation behavior.
- **Float pinning (2026-07-15):** Pandoc's `--from markdown` default enables `implicit_figures`, converting `![alt](path)` images into LaTeX `\begin{figure}` floats. Mid-body images drift to page top without `\floatplacement{figure}{H}`. The shared default template loads `\usepackage{float}` + `\floatplacement{figure}{H}` to pin figures exactly at marker position. Risk: tall diagrams on a full page cause whitespace gaps (preferable to incorrect ordering). Template directory is fingerprinted → all docs regenerate automatically.
- **Fence-aware markers (2026-07-15):** `DiagramMarkers.GetFencedRanges` uses a CommonMark line-based state machine. Handles labeled fences (` ```csharp `), indented fences (≤3 spaces), tilde fences, and unclosed fences (runs to EOF). Fixes round-2 regex bug: bare-fence-only `^(```+|~~~+)\s*$` missed labeled openers and misclassified bare closers of labeled blocks as new openers. `FindReferencedKeys` and `Substitute` skip markers inside fences. Web path (Markdig HTML-escapes `<!--`) is naturally immune. Tests cover: labeled fences, markers between labeled blocks (not misclassified), unclosed fences, indented fences.
- **Global DiagramIndex (2026-07-15):** `ResolveSegments` uses a single global instance counter instead of per-key counts. Two distinct diagrams on one page now get sequential ids (0, 1) instead of colliding at 0. `FindDuplicateKeys` helper surfaces duplicate frontmatter keys for caller warnings; both web path (`Blog.razor`) and PDF path (`GenerateOneAsync`) log warnings on duplicates. CI backstop: `DiagramContentHygieneTests` fails build on duplicates in real content.
- **Markdig/Pandoc list parity (2026-07-15):** Markdig (CommonMark) allows `- ` lists immediately after paragraphs without blank lines. Pandoc's `markdown` input requires blank lines before lists. `PdfGeneratorService` now uses `--from markdown+lists_without_preceding_blankline` to match Markdig behavior. Affects 18 material files. Extension confirmed present in pinned Pandoc 3.10 via `--list-extensions=markdown`.
- **Mermaid palette (2026-07-15):** `.mmdc.json` `fontSize` 12→14; `mainBkg` changed from `#ffffff` to `#dbeafe` (Mermaid uses `mainBkg` for flowchart nodes AND sequence-diagram actors — it overrides `primaryColor` for these elements). Added explicit sequence variables: `actorBkg`, `actorBorder`, `actorTextColor`, `actorLineColor`, `signalColor`, `signalTextColor`, `activationBkgColor`, `activationBorderColor`, `noteBkgColor`, `noteBorderColor`, `labelBoxBkgColor`, `labelBoxBorderColor`. Semantic `classDef` colors in content (red `#ef4444` / green `#16a34a`) untouched.
- **PDF label color fidelity (2026-07-15):** mermaid-cli's `-e pdf` export prints the page through Chrome, whose print color-adjust darkens light HTML label text (classDef `color:#ffffff` rendered as `#ABABAB` gray in the PDF while SVG/PNG exports stayed white — confirmed by dumping PDF `rg` fill operators). `"flowchart": { "htmlLabels": false }` in `.mmdc.json` is IGNORED by this render path; the top-level `"htmlLabels": false` key is what actually switches node labels to SVG `<text>`, which prints with exact fills. This also matches the web render, where strict `securityLevel` forces SVG labels. Verification path: render a classDef-colored flowchart with the repo CLI (`node node_modules/@mermaid-js/mermaid-cli/src/cli.js -i x.mmd -o x.pdf -e pdf -c .mmdc.json --pdfFit`, `PUPPETEER_CACHE_DIR=artifacts/puppeteer`) and grep decompressed streams for `.6706 .6706 .6706 rg` (absent) vs `1 1 1 rg` (present).
- **Tilde fences (2026-07-15):** CommonMark allows info strings on tilde fences (`~~~python`), including backticks; only backtick-fence info strings may not contain backticks. `IsValidFenceOpener` initially rejected labeled tilde fences, making them invisible to marker scanning; fixed (any info string valid for `~`), covered by `FindReferencedKeys_IgnoresMarkerInsideLabeledTildeFence` (verified red without the fix). `GeneratorSchemaVersion` 6→7 for this behavior change.
